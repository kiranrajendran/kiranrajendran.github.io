# AGENTS.md

## Project Overview

Personal portfolio/blog site at `kiranr.com`, built with **Jekyll** (Ruby static site generator) and a custom theme. Asset compilation is handled by **Gulp 4** (JS, SCSS, images, YAML config assembly). The site is deployed via GitHub Pages from the `master` branch.

---

## Commands

### Local Development
```bash
bash b.sh                        # shortcut: bundle exec jekyll serve --force_polling
bundle exec jekyll serve         # standard Jekyll dev server (outputs to _site/)
gulp                             # full pipeline: build JS/theme/images/config, Jekyll build, BrowserSync + file watchers
```

### Production Build
```bash
gulp build                       # compile JS + theme + images + config, then jekyll build (no server)
```

### New Post
```bash
./initpost.sh -c <Post Title Here>   # generates a dated markdown file in _posts/ with pre-filled front matter
```

## Architecture

### Config Assembly (Critical Gotcha)

`_config.yml` at the repo root is **generated by Gulp**, not hand-edited. The source of truth lives in `src/yml/`:

| File | Purpose |
|---|---|
| `src/yml/site.yml` | Site name, title, description, menu, email, Disqus |
| `src/yml/social.yml` | Social media usernames |
| `src/yml/theme.yml` | Theme color variables (fed to SCSS via JSON intermediary) |
| `src/yml/advanced.yml` | baseurl, url, Google Analytics, categories folder, language |
| `src/yml/posts.yml` | Pagination/layout toggles (time bar, modal, two-column layout) |
| `src/yml/translations.yml` | i18n strings |

**Never directly edit `_config.yml`** - changes will be overwritten by `gulp config`. Edit the relevant `src/yml/*.yml` file instead.

### Theme Colors (Non-obvious pipeline)

`src/yml/theme.yml` → (gulp-yaml) → `src/tmp/theme.json` → (json-sass) → `_sass/_theme.scss` → compiled into CSS. Editing `_sass/_theme.scss` directly will be overwritten; edit `src/yml/theme.yml`.

### JavaScript

- Source: `src/js/main/**/*.js` → minified & concatenated → `assets/js/scripts.min.js`
- Preview widgets: `src/js/preview/**/*` → copied as-is to `assets/js/`
- Key libs in `src/js/main/`: `zmain.js` (entry), `simpleJekyllSearch.js`, `timeBar.js`, `ouibounce.js`, `smoothscroll.js`, `scrollanimation.js`, `recommendation.js`

### SCSS

Partials live in `_sass/`. Entry points: `main.scss`, `jekflix.scss`, `portfolYOU.scss`, `autumn.scss`, `preview.scss`. Variables are in `_sass/_variables.scss`; theme-generated colors are in `_sass/_theme.scss` (do not edit directly).

## Content Structure

### Posts (`_posts/`)

Jekyll convention: filenames must be `YYYY-MM-DD-slug.md`.

Required front matter:
```yaml
---
date: YYYY-MM-DD HH:MM:SS
layout: post
title: "Human Readable Title"
subtitle:
description:
image: https://...       # full-width image (680px wide on Cloudinary)
optimized_image: https://...  # thumbnail (380px wide on Cloudinary)
category: <slug>         # must match a file in category/
tags:
  - tag1
author: kiranrajendran
paginate: false
---
```

Images are hosted on **Cloudinary** (`dvexqgcid` account). Use `c_scale,w_680` for `image` and `c_scale,w_380` for `optimized_image`.

Local post images go to `assets/post-images/` and are referenced as `/assets/post-images/filename.png`.

### Categories (`category/`)

Each category must have its own `.md` file with:
```yaml
---
layout: category
title: Blog
slug: blog
description: A category description.
---
```

The slug matches the `category:` field in post front matter.

### Pages (`pages/`)

Static pages use `layout: page` with a `permalink:` field.

### Oposts (`oposts/`)

Sample/demo posts from the original theme - not live content, kept for reference.

## Layouts

All layouts are in `_layouts/`. Key ones:
- `post.html` - blog post
- `home.html` / `main.html` - landing/index
- `page.html` - static pages
- `category.html` / `tags.html` - taxonomy pages
- `compress.html` - HTML minification wrapper

Includes live in `_includes/` and are organized into subdirectories (`blog/`, `about/`, `projects/`, `elements/`).

---

## Plugins (`_plugins/`)

Custom Jekyll filters and tags live in `_plugins/filters/` and `_plugins/tags/`. These run at build time.

---

## Test Directory

`test/Gemfile` references the gemspec at the repo root via `gemspec :path => "../"`. Running tests from `test/` validates the gem packaging, not the site content.

---

## Deployment

The site deploys via **GitHub Pages** from the `master` branch. The `CNAME` file contains the custom domain. The `docs/` directory exists but appears unused (has only a `.gitignore`). The built `_site/` directory is typically excluded from the repo (check `.gitignore`).

## Gotchas

- **Edit `src/yml/` not `_config.yml`** - the root config is generated.
- **Edit `src/yml/theme.yml` not `_sass/_theme.scss`** - theme SCSS is generated.
- The `gulp` default task starts BrowserSync and watchers; use `gulp build` for CI/headless builds.
- `b.sh` uses `--force_polling` which is needed in some environments (WSL, network mounts) where inotify doesn't work.
- `initpost.sh` creates files in `_posts/` relative to the script's location, not `cwd`.
- Post `author:` field value (`kiranrajendran`) must match the author slug used in the theme's author lookup.
